# Project Iris audit — 2026-10-25

This is the first honest code audit of the repository, not a claim that a clean build means
the product is finished. I inspected the application shell, every app view/control, the core
runtime, brain turn loop, memory graph, voice path, perception path, module router, plugins,
settings, tray lifecycle, scripts and the design brief.

## Verification baseline

* Stack: .NET 9, Avalonia 11.2.3, C# code-built UI, Windows target.
* `dotnet build CompanionOS.sln -p:BaseOutputPath=verify-bin -v:minimal` — **passed, 0 warnings, 0 errors**.
* A new `CompanionOS.Core.Tests` project now covers three high-risk regressions: mode-state
  events, quoted server arguments and transactional memory deletion.
* Runtime smoke: the rebuilt app started in an isolated temporary `COMPANIONOS_HOME`, created
  its system log, reached the visible boot path and stayed alive for four seconds before the
  smoke process was intentionally stopped. Visual interaction verification is still required
  with a restarted build; the existing user `CompanionOS` process was not killed.
* The repository is not a Git working tree, so this audit cannot provide a commit diff or
  preserve a pre-audit revision automatically.

## Fixed in this pass

### Critical interaction and rendering defects

1. **Overlay compact state was not compact.** `OverlayWindow.ApplyShape` left the button host
   visible for the compact shape. The 64 DIP window therefore painted three controls outside
   its own frame on first paint, matching the broken screenshot/flicker report. The host now
   appears only for the explicit hover/button shape.
2. **Overlay position setting was effectively dead after a drag.** A saved pixel position
   always won over the corner dropdown. Choosing a corner now clears the pixel override.
3. **Chat had no stop action while thinking.** The composer now changes Send to Stop while a
   turn is active and calls the real cancellation path.
4. **Chat did not honor Shift+Enter.** The composer now accepts multiline input while plain
   Enter still sends.
5. **Long tool activity could paint outside its row.** Tool activity now wraps instead of
   using an unbounded no-wrap line.
6. **Streaming assistant bubbles were blank before the first token.** They now show the
   honest streaming placeholder immediately.
7. **Error orb shake was never armed.** Entering `MindState.Error` now starts the configured
   two-shake motion instead of only changing colour.
8. **VoiceWave geometry exceeded its view box.** The rightmost bars were clipped; the glyph
   now stays within the 24-unit icon box.

### State, concurrency and lifecycle defects

9. **Gaming/sleep transitions could race.** Automatic game detection, idle sleep, a user
   command and a wake request could all start/stop the cortex concurrently. A mode gate now
   serializes these operations, and the authoritative operating mode is published before
   process teardown begins.
10. **Mode changes silently mutated the mind state.** `MoveModeTo` changed the internal state
    without raising `StateChanged`, leaving the orb and overlay stale until another event.
    It now publishes the derived state transition too.
11. **Stopping llama-server blocked the caller synchronously.** The old `WaitForExit(5000)`
    could freeze the UI thread. Shutdown now awaits `WaitForExitAsync` with a bounded timeout.
12. **Multiple speech segments could transcribe concurrently.** A recognition gate now keeps
    Whisper/HTTP transcription serial, preventing a noisy room from creating a CPU and event
    storm.
13. **The mic could report OPEN with no recognizer.** Explicitly opening the mic now refuses
    honestly and shows a warning when neither the local model nor HTTP recognizer is usable.
14. **Old audio playback completions could stop new audio.** The shared player now uses a
    playback generation so an old `finally` block cannot tear down a newer clip.
15. **EventBus telemetry count was racy.** Published event count now uses an atomic counter.

### Capability and data-integrity defects

16. **The core router starved optional modules.** Core exposed eight tools before routing,
    exactly filling the eight-tool budget, so Music and System Control could never reach the
    model. Core tools are now selected by relevance with a four-tool core budget, leaving room
    for routed modules.
17. **Plugins were loaded and shown but never registered as callable modules.** A validated
    plugin adapter now registers non-disabled plugins with ModuleHost, routing, sandbox and
    the model. Plugin tools default to system-critical permission because they execute outside
    the trusted built-in process.
18. **MCP pending requests were not thread-safe.** Response matching and timeout removal now
    use a lock; MCP startup is serialized; stderr is drained; pending requests are completed
    on disposal.
19. **Command-plugin stdout/stderr could deadlock.** Both streams are now drained concurrently.
20. **Memory deletion used two autocommit SQL statements.** Node and synapse deletion now uses
    one SQLite transaction, so a power loss cannot leave half a deletion.
21. **Perception shared and mutated the live snapshot object across threads.** Ambient and
    media refreshes now clone/copy snapshot data before mutation.
22. **Permission UI timeout only hid the card.** It now cancels the underlying request as a
    refusal instead of leaving the tool waiting for the second timeout.

## High-risk areas still open

These are real remaining gaps, not invented roadmap filler:

* **Test coverage is still narrow.** The new regression suite covers the most dangerous fixes,
  but tool routing, permission expiry, audio generation replacement, plugin JSON-RPC and
  settings recovery still need dedicated tests. This remains the largest engineering-quality
  gap.
* **No restarted visual pass yet.** The corrected binary builds, but the currently running
  process is an older instance. The overlay must be checked at 100%, 125% and 150% scaling;
  the full shell must be checked at the 980×640 minimum; and keyboard focus/resize behavior
  needs a real interaction pass.
* **System-wide hotkeys are still not implemented.** `Ctrl+M`, screen capture and navigation
  work only while a CompanionOS window has focus, as documented in `PLACEHOLDERS.md`.
* **Plugin trust policy is conservative but coarse.** Every external plugin tool asks as
  system-critical; there is not yet a user-facing per-plugin capability review/grant editor.
* **Voice profile application always rebuilds the HTTP synthesizer.** That matches the current
  one-engine product decision, but future engine selection needs a factory rather than a hard
  coded `HttpSpeechSynthesizer` in `ApplyVoiceProfileAsync`.
* **The design system is still code-only and lacks screenshot regression tests.** A grade-A
  visual product needs reference screenshots or an equivalent scripted UI checklist, not only
  source inspection.
* **The running process can lock normal build output.** The build remains valid, but the normal
  `scripts/run.ps1` path should stop/reuse the active instance or direct verification builds
  to a separate output folder.

## Product-level conclusion

The repository was not merely “a few alignment bugs.” It had several cross-layer defects that
made the product feel random: a compact overlay that rendered expanded children, a router that
made optional capabilities unreachable, a mode machine that could race itself, stale visual
state after mode changes, and plugin infrastructure disconnected from the model. Those are
now addressed in code and the solution builds cleanly.

It is **not yet A-grade** until the open items above are closed, especially tests and a real
visual/runtime pass on a restarted build. The next engineering milestone should be a focused
test harness plus a scripted interaction matrix, not another broad visual rewrite.
